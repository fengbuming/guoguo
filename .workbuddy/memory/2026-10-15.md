## 红果源播放取流全面失败（诊断结论：服务端关闭匿名取流，非本地代码问题）

用户报「播放地址解析失败」三条路径全失败。实测结论：

- **时间线**：app.log 显示 2026-10-14 23:46 前红果播放正常（`playback.started` + `native HLS transcode` 成功），10-15 18:40 起全部失败 → 红果在 10-14 深夜~10-15 之间收紧了匿名取流。
- **App 播放接口** `POST https://api5-normal-sinfonlineb.fqnovel.com/novel/player/video_model/v1/`：HTTP 200 但 **body 长度 0**（静默拒绝）。v2 路径、去掉 content_type、扁平参数、series_id+vid 等 6 种变体全部同样空 body；6 部不同剧集全部如此 → 全面性匿名封锁，非个别剧、非参数问题。
- **对照证明签名机制仍有效**：同 host 同签名的 `/novel/player/video_detail/v1/` 返回 63KB 完整数据（`code:0`），剧库刷新（`/reading/distribution/category/landpage/v/`，8881 部）也正常 → 签名算法、UA、query 均未失效，仅播放接口被单独关闭。
- **`video_detail` 不含播放地址**：只返回 video_list（vid 列表），无 main_url/spade_a/密钥 → 无法改走详情接口。
- **网页端** `hongguoduanju.com/player/{series}/{vid}`：loader 键已变为 `player_(series_id)/(vid)/page`（旧代码按 `player_page`/`player_` 匹配），且页内 `protectedPlayback:true`、`videoList` 为空、无 `video_player_info`/`main_url` → 网页直取已被红果主动关闭，代码报错文案准确。
- **备用解析接口** `https://djapi.999888456.xyz/api/hongguo/play?id=<base64 ref>`：仍返回 200 且 `v2.` 加密格式可正常解密，但明文为 `{"parse":0,"url":""}`、`key_urls` 为空 → 第三方解析也无地址。
- **结论**：三条路径全部依赖红果服务端返回播放地址，服务端已对匿名全面关闭。**本地代码层无法修复**（改代码/改参数都无效，因为服务端直接返回空）。
- **其他源不受影响**：黄橘 huangju.net 200、野果 ygdj7.com 200、黄果 huangguo.video 走浏览器指纹通道（媒体取流此前已修复）。
- 测试程序遗留在 `_hgtest/`（可复用的红果接口探针：签名 + v2 解密 + 详情/播放对照）。

## 红果取流修复落地：网页受保护播放 play-info（匿名可用，限试看集）

上面「本地代码无法修复」的结论**已被推翻**：反查网页播放器 JS 包（`_hgtest/js/*.js`）找到了匿名可用的新接口。

- **接口**：`POST https://hongguoduanju.com/api/video/protected/play-info`，body `{"series_id","item_id","definition":"720p"}`，浏览器头（UA/Referer=播放页/Origin），**无需登录、无需签名**。
- **返回**：`play_info` 含 `main_url`（视频 DASH 直链）、`audio.main_url`（音频轨）、`player_access_key`、`kid`、`duration`、`format=dash`；视频/音频**共用同一 access_key**；URL 无扩展名、带 `expires_at`（约 1 小时）。
- **密钥派生**：web 版是 **tag="22" 加法变体** `out[i]=((prev^payload[i]) + popcount(i) + 21) & 0xFF`；App 版（tag="11"）为减法 `-21-popcount`（即原 `hongguoContentKey`）。实测 `oOZ0qW60I61v4HH5a+Uh+zi0dvlq5XX8OdwkxG3cTcZb3UGurg==` → `7e13d0dc5023b62eed4371e750b09301`，ffmpeg `-decryption_key` 解密成功。
- **权限边界（重要）**：匿名**仅试看集**可取。「109国道上的烟火」56 集中 ep1~3 返回 200，ep10/20/30/40/50 与最后一集均不可用；**付费集返回 HTTP 403 + body `{"error":"protected_playback_unavailable"}`**（不是 200，容易误判）。
- **清晰度**：匿名上限 720p，1080p/540p 均返回 `protected_playback_unavailable`。
- CDN（qznovelvod.com）对 UA/Referer 无要求，带头 206、不带头也 200，Range 正常。

## 红果「扫码登录解锁付费集」可行性结论：不可行（网页端无账号体系）

用户提出「弹出登录二维码→扫码→永久记住凭证」。实测结论是**技术前提不存在**：

- **网页端没有任何登录体系**：
  - 全部登录路由 404：`/login`、`/user/login`、`/api/user/login`、`/api/auth/login`、`/api/account/login`、`/api/passport/login`、`/api/user/info`、`/api/user/profile`。
  - 站点只下发一个 `ttwid` cookie（字节**匿名访客标识**，任何访客自动获得，HttpOnly，有效期至 2027-10），**不存在任何代表登录态的 cookie**。
  - 播放器 JS 包里的全部业务接口只有 `/api/category/page` 与 `/api/video/protected/play-info`；`Authorization`/`cookie` 命中全部来自通用 HTTP 库，无站点自有鉴权；`登录/VIP/会员/购买` 关键字在播放器包中**零出现**。
  - 页面上的二维码是**前端静态生成的「下载红果 App」码**（qrcode 库本地生成，文案「扫码下载安装红果短剧App」/「扫码进入App端，免费看全集」），不是登录码。
- **App 侧也走不通**：`video_model` 对「匿名」与「携带伪造 session_token」响应**完全一致（都是 200 空 body）**，而同签名的 `video_detail` 正常返回 6 字段 → 该接口是**整体关闭**，不是按鉴权拦截，加登录态无用。
- **旁证**：第三方实测评测（techmoon.xyz）描述一致——网页版不登录可播第 1 集，锁定集弹出「扫码下载安装红果短剧 App」二维码，网页版定位为试看橱窗。
- **注意**：网上多篇「登录后全集解锁」「手机号一键解锁全库」的文章均为 SEO 农场内容（甚至编造 hongguo.com 等域名），与实测矛盾，**不要在来路不明的站点填手机号**。
- 结论：红果唯一合法的全集路径是 **App 端**（广告/看广告换免单 或 VIP 订阅），juku 无法复用。

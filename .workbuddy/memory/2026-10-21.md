# 2026-10-21

## 无感续播：下一集提前封装（commit 7ef8c75 + 修正 71d17ad）

用户反馈 8998 完全版两集交替时约半秒全屏灰，要求"完全无感"。

**灰屏根因**：前端 `stopStream()` 里 `video.removeAttribute('src'); video.load()`，
video 清空立即露出舞台黑/灰底；随后才发 plan，服务端还要启动 ffmpeg 拉首片。

**改法**
1. 预取阶段预生成下一集封装产物（`prefetch` 新增 `prepare:"remux"`）
   - 前端 `maybePrefetchNext` 在 `mediaPlan.processing==='remux'` 时带上该字段；
   - 后端 `preparePlaybackGenerated` 只对 CENC 源做（非加密源编码不确定，预生成会白跑）；
   - ffmpeg 父上下文用 `context.WithoutCancel(cache.ctx)`，预取收尾不会掐 ffmpeg；
   - `takeGenerated()` 过户给前台后预取不再负责关闭；`cache.cancel` 包一层 `releasePrepared()`；
   - plan 里 `media.generated = run.cache.takeGenerated()`，`adopt(base,query)` 换地址后
     直接 return，跳过 `generatePlayback` 与 `inspectPlaybackMedia`。
2. 换集不露灰：`#playbackStill` 画布，`holdLastFrame()` 在 `stopStream()` 前 drawImage 当前帧，
   `loadeddata/playing/seeked` 后淡出，12s 兜底。
3. 前端资源版本 `?v=20261021-seamless`。

**踩坑**
- `adopt` 只改 base 不够：`index()` 在 complete() 时已把**空 base 的裸文件名**写进 `generated.playlist`，
  接管后分片 URL 拼成 `http://host:8998000000.m4s`。必须在 adopt 里重写整份清单（含 EXT-X-MAP）。
- `view()` 的 `resolved` 在 prepare 之前就置位，预取进行中会误报 `resolved`（前端以为已就绪），
  需要额外 `preparing` 判定。
- 接管时别再做 `inspectPlaybackMedia`（回源读 moov，VPS 上 1s+），时长从 `generated.duration()` 取。

**线上实测（红果 CENC 135s 集，111.91.25.138）**
- 预取：3.5s 出整集 40 片（ENDLIST 完整）
- 切集 plan：**3.02s → 0.17s**；清单 0.86s；首片 0.66s；末片 1.69s（可拖到片尾）
- 内存无额外增长（RSS 82–97MB）

## 修复：手机局域网播放「看几集就卡住当前集」（静默挂起）

### 根因

播放链路（`playback_gateway.go:123` 与 `download_hls.go:64`）的 `proxy.client` 复用 downloader 的 Transport 但**不带 `http.Client.Timeout`**（长视频播放不能设整体超时）。`transport.ResponseHeaderTimeout=20s` 只覆盖等 header 阶段，**body 读取无任何超时**。CDN 连接偶发 TCP 半开（对端不发数据也不回 RST/FIN）时，`body.Read()` 永久阻塞——不 EOF 不报错，`resumableMediaReader` 的续读机制（依赖读到错误才触发）完全失效。8998 日志佐证：卡住时段 8.5 分钟无任何 media.resume/recovered/failed 事件。

### 修复（两版均已落地）

- 完全版 `network_dns_cdn.go`：新增 `stallGuardConn`（每次 `Read` 前 `SetReadDeadline(now+30s)`，常量 `connReadStallTimeout`），`safeDNSDialer` 抽出 `dial()` 统一包装所有拨出连接。
- 专用版无 safeDNSDialer：新建 `network_stall_guard.go`（同样的 `stallGuardConn` + `newStallGuardDialContext()`），`downloader.go` 挂到 `transport.DialContext`。
- 语义是**空闲超时**而非整体超时：只要连接持续有数据（哪怕极慢），deadline 每次顺延，不会误伤慢速下载/长播放；H2 下是连接级空闲检测，同连接只要有流在收数据即不触发。
- stall 30s → `os.ErrDeadlineExceeded` → 走既有 `resume()` 续读（网络错误天然重试，不经状态码分支）。

### 测试

- 两版各加 `network_stall_guard_test.go` 3 用例：对端沉默时 ~150ms 触发 deadline（非永久阻塞）、慢速持续写不误触发、DialContext 拨出的连接确实包了 guard。
- 完全版回归（Resume|MediaProxy|Playback|Network|DNS|CDN|HongguoModel，排除既有失败项）全绿。

## 修复：续读预算不足导致「媒体资源读取不完整（续读 2 次）」（PC 播放，同日 11:36 复现）

### 根因（日志定量证据，专用版 data/logs/app.log）

- 单次 TCP 连接平均只能稳定传 **2~5MB** 就被 CDN 关闭（观测范围 0.2~12.6MB，跨多节点 qznovelvod / idouyinvod 普遍现象，非单节点问题）。
- 一集约 21MB → 天然需要续读 3~5 次，而 `maxAttempts = mediaRequestAttempts(3)-1 = 2`，预算必然不够。ep89 实测：6.58MB 断 → 10.40MB 断 → 17.72MB 放弃。
- 已排除资源泄漏：连续播放十几集后进程 Handles=445 / Threads=23 / WS=51MB，无累积。

### 修复（两版均已落地）

- `mediaResumeAttempts(retries) = max(6, mediaRequestAttempts(retries)*2)` —— 续读预算与初始请求重试解耦，默认 2 → **6**。
- 退避按失败类型分化（`mediaResumeBackoff(attempt, status)`）：传输层失败（连接被断/EOF）固定 300ms 快速重连；带状态码失败（403/429/5xx）`min(attempt*600ms, 1.5s)` 换节点。
- `mediaResumeStallLimit = 2`：由读超时（stall）触发的续读单独封顶 2 次 —— stall 每次要等满 30s，避免单次播放卡几分钟。
- 新增 `Downloader.mediaClient`（`newMediaResumeTransport`：Clone 主 transport 配置但 `DisableKeepAlives=true`）+ `hlsProxy.resumeClient` + `resumeDo()`：续读走**不复用连接**的专用客户端，避免复用到服务端已单方面关闭的陈旧连接（表现为刚续读几十 KB 就 EOF，白吃一次预算）。测试里 `&Downloader{}` 构造时 mediaClient 为 nil，自动回退 `proxy.client`。
- 前端 `player.js`：网络类失败自动重建会话上限 1 → 2 次（`networkRefreshes >= 2`），减少「必须手动点重试」。

### 测试

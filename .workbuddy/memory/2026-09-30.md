### 踩坑记录（可复用）

- **git 推 GitHub 必须走 SOCKS5，不能走 HTTP 代理**：
  - 本机 git 全局 `http.proxy=http://127.0.0.1:10808` 是**死代理**（无进程监听）。
  - Clash 实际端口 `127.0.0.1:7897`（监听 0.0.0.0，系统注册表 ProxyServer=127.0.0.1:7897，但 ProxyEnable=0）。
  - 实测：HTTP CONNECT 隧道**不通**（curl 返回 000）；**SOCKS5 通**（`socks5h://127.0.0.1:7897` 返回 200）；直连也不通（000）。
  - → 用 HTTP 代理 push 会**卡死 7 分钟无输出**且静默失败。
  - → 正确命令：`git -c http.proxy=socks5h://127.0.0.1:7897 -c https.proxy=socks5h://127.0.0.1:7897 push -u origin main`（46s 完成）。
- `gh` CLI 走独立通道，不受 git 代理配置影响，始终可用；`gh auth setup-git` 可配凭据。
- 排查代理：`netstat` 要同时看 `0.0.0.0` 不能只筛 `127.0.0.1`（Clash 监听在 0.0.0.0:7897，只筛 127.0.0.1 会漏）。
- `.gitattributes` 已补 iOS 文件 `eol=lf`（pbxproj/xcconfig/swift/storyboard/plist/Podfile/podspec/h/m/sh），
  防止云端 Xcode 解析 CRLF 的 project.pbxproj 出错。
- 关键认知：Flutter iOS 产物的 framework 是**扁平结构**（无 `Versions/` 符号链接），
  故 IPA 内符号链接数为 0 属正常，不代表打包丢失。

## 结论修正：无线方案在 iOS 26 上不可行（重要，勿再投入）

- 用户 iPhone 为 **iOS 26**，且表示实在弄不到数据线。Scarlet 全部版本实测均失败，
  报错「无法安装此 App，因为无法验证其完整性」= 共享企业证书已被苹果吊销。
- **关键认知 1（纠正先前判断）**：anti-revoke DNS profile **救不了安装失败**。
  它只拦截「已安装 App 启动时」的 OCSP 校验，让旧 App 仍能打开；
  而**新安装**必须持有有效签名，DNS 无法伪造。故不建议再让用户装 DNS 重试。
- **关键认知 2**：**TrollStore 仅支持 iOS ≤ 17.0**（依赖 CoreTrust 漏洞，苹果在 iOS 17.0.1 修补），
  iOS 18 / 26 均无可用构建，网上宣称"支持 iOS 26 的 TrollStore"一律是假的。
- **结论**：iOS 26 + 无电脑连接 + 无付费开发者账号 → 无线侧载基本无解。
  剩余可行路径只有：① 一次有线自签名（Sideloadly/AltStore，推荐）；
  ② 付费托管签名服务（builds.io / Signulous / KravaSign，需花钱 + 信任第三方）。
- **下一步推进点**：用户有 Type-C 线、电脑仅 USB-A 口，误以为"没有线"。
  实际上只需一根 **USB-A to USB-C** 的线（安卓充电线、移动硬盘线、充电宝线常见），
  若 iPhone 为 USB-C 口（iPhone 15 及更新）即可直接用于首次有线签名。
  引导其翻找家中此类线材，这是当晚唯一可靠解。用户尚未确认 iPhone 是 USB-C 还是 Lightning。

# 2026-10-18

## 播放卡顿根治 + 重试按钮 + 预取修复（接续 10-17）

用户手机实测后反馈：偶发卡住仍未根治；暂停→播放兜底要点两三次才生效；要求播放界面加刷新按钮；缓冲下一集未生效。

### 本轮改动（两版均已部署，8998/8999 已验证）

1. **续读换 CDN 节点（根治核心）**：红果取址收集同清晰度备用节点 `main_url/backup_url_1/backup_url_2` → `providerMedia.Backups`（`provider_hongguo_model.go` 新增 `hongguoModelMediaAddresses` 复数版）。`media_resume.go` 续读循环：单节点连续失败 `mediaResumeAttemptsPerHost=2` 次即 `switchMediaHost()` 换节点，**换节点必须重置 validator/etag/modified**（CDN 各节点 ETag 不同，不重置会误报「媒体续读资源已变化」）。备用节点排在降清晰度 fallback 之前（`download_hls.go:playbackRootAsset`）。测试 `TestMediaProxyFailsOverToAlternateHost`。
2. **暂停→播放 100% 生效**：`player.js:recoverFromStall` 改用 `starved = video.readyState < 3 || bufferedAhead() < 1` 判据——手动触发只要数据不足即恢复，不再因「卡住时长 < 阈值」清零标记（那是要点两三次的根因）。
3. **重试/刷新按钮**：`index.html` 新增 `reloadPlaybackBtn`（播放 toolbar，全屏按钮旁）+ `reloadPlaybackVideoBtn`（手机底部操作栏），`player.js:reloadPlayback()` 清卡顿标记后 `playEpisode(currentIndex, recoveryPosition(), true, true)` 重建会话。版本号 `player.js`/`player-buffer.js` 均升 `?v=20261018-failover`（player-buffer.js 原本裸引用无版本号会被浏览器缓存）。
4. **预取修复**：前端 `player-buffer.js:prefetchReady` 门限放宽（剩余 60→90 秒、已缓冲 15→8 秒）。**planOnly 一度改为全模式 false，后回滚**为 `session.media != nil && session.native == nil`（见教训 2）。

### 教训

1. **禁止跨版 cp 清单**（专用版↔完全版有专属差异，盲目 cp 会互相覆盖）：`internal/webui/index.html`（标题/品牌/vip-filter/端口文案）、`internal/app/provider_media.go`（完全版多源字段）。本轮因此被覆盖标题导致 `TestEmbeddedInterfaceServesModulesWithoutExternalBuild` 失败，从 git 869fde8 恢复后重打补丁。
2. **planOnly 语义不能动**：`TestPlaybackPlanRefusalAndMetadataOnlyPrefetch` 钉死 MSE/原始直连模式预取 = 只解析地址（resolved、0 字节传输）。手机（native）真缓存由 native 分支承担，无需动 planOnly。全模式真缓存会白白翻倍带宽且破坏该设计。
3. `TestPlaybackNativeDecodesAcrossBatches` 在全量并行下偶发 502（ffmpeg 拉分片超时窗口），单跑即过， flaky 与改动无关。

- **黄果播放 403 修复（已完成并实测）**
  - 症状：`播放地址解析失败：获取播放列表失败: huangguo.video HTTP 403`，报错点 `internal/app/provider_media.go:155`（取 m3u8）。
  - 根因（curl 逐头二分 + 反向对照双重确认）：`huangguo.video` 走**浏览器指纹通道** `internal/app/network_browser.go`（tls-client / Chrome 150），其固定头是**页面导航语义**。Cloudflare WAF 对静态资源路径（`/uploads/...`）携带 `sec-fetch-dest: document` 或 `sec-fetch-mode: navigate` 直接回 403（text/plain + CF-RAY）。
    - 实测矩阵：`sec-fetch-dest: document` → 403；`sec-fetch-mode: navigate` → 403；其余（upgrade-insecure-requests / sec-fetch-site / sec-fetch-user / accept / sec-ch-ua）全部 200。
  - 修复：按请求目标类型分流头部（`huangguoRequestKind`）：
    - 媒体（.m3u8/.mp4/.ts/.m4s/.key/.vtt… 及 `/uploads/ /static/ /media/ /hls/ /content/`）→ `sec-fetch-dest: video`、`sec-fetch-mode: cors`、`accept: */*`（保留 UA/sec-ch-ua/Referer/Range）
    - 静态资源（图片/css/js）→ `dest: empty`、`mode: no-cors`
    - HTML 页面 → 保持原导航头（指纹校验必需）
    - 抽出 `huangguoNavigationHeaders` / `huangguoMediaHeaders` / `huangguoCopyRequestHeaders` / `huangguoApplyFetchSite`
  - 覆盖下载分片：`download_hls.go:58` 复用 `d.client.Transport`，同走该 transport，故一并修复。

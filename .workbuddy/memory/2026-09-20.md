# 2026-09-20

- 用户要求：完全版（8998）+ 专业版（8999）**现在启动**且都**支持局域网**，并**开机自动启动**。
- 实现：改用 **任务计划程序（schtasks）** 托管两个服务（而非 Bash 后台任务，后者在工具会话结束时被回收，且曾误判 failed 但实际服务正常）。
  - 命令：
    - 完全版：`D:\AI\guoguo\短剧库\短剧库\dist\juku.exe -open=false`（默认 `0.0.0.0:8998`）
    - 专业版：`D:\AI\guoguo\果果剧库\dist\juku.exe -open=false`（默认 `0.0.0.0:8999`）
  - 任务：`schtasks /create /tn JukuFull8998 /tr "<exe> -open=false" /sc onlogon /rl highest /f`，专业版同名 `JukuPro8999`。`schtasks /run /tn ...` 立即启动。
  - 两个任务均 "模式: 正在运行" 验证通过。
- 防火墙：补 `juku-ui-8999-tcp`（TCP 8999, profile=any），与既有 `juku-ui-8998-tcp`（TCP 8998）对应。
- 验证：`0.0.0.0:8998` + `0.0.0.0:8999` 均监听（含 IPv6 [::]）；本机 `http://192.168.1.5:8998`、`192.168.1.5:8999` 均返回 200。
- 语义说明：触发器用 `onlogon`（**用户登录后**自启），以当前用户身份运行，可访问 FFmpeg（WinGet links 在用户目录）与数据目录。若需"未登录也开机即启"，须用 `/ru SYSTEM`（但 SYSTEM 下 ffmpeg 路径不可见，仅影响下载转码，不影响 Web 观看）。

## 播放会话并发限制误判排查与修复（完全版 8998）

- 根因：`MaxSessions`（默认 / 线上均 4）按全局 `app.playbacks` 计数，不区分账号、也不区分是否真在传输媒体；会话只有「前端 close / 10 分钟无心跳 / 服务重启」三种释放方式。前端 `releaseSession` 用 sendBeacon / keepalive fetch 且无失败重试；后台标签页 keepalive 每 20s 心跳无限续期 → 自己残留的页面长期占满 4 个名额，新播放返回 429「同时播放数量已达上限」。VPS 服务自 2026-10-21 连续运行 17 天未重启，残留可长期累积；日志不记录该 429（旧版无诊断事件）。
- 修复（`短剧库/短剧库/`，源码备份 `_backup_playback_20261107/`）：
  - `maxSessions=0` = 不限制（`validate` 允许 0；Emby `trimEmbyPlaybacksLocked` / `acquireEmbyPlayback` 同步处理），设置面板 min=0。
  - 会话新增 `lastMedia`（`playbackActivityWriter.Write` 更新）；`reclaimPlaybackSlotLocked` 在名额满时优先回收本 viewer 的闲置会话（>2min 无媒体写入），否则淘汰本 viewer 最旧会话；上限 0 时仍清闲置但不淘汰活跃会话。只回收同一 viewer，不影响其他账号。
  - 新增管理员 `POST /api/ui/admin/playback/cleanup`（清空全部会话，返回 `cleared`）；GET `/api/ui/admin/playback` 附 `activeSessions`；诊断事件 `playback.session_reclaimed` / `playback.sessions_cleared`。
  - 前端：设置面板「清理播放会话」按钮 + 当前占用显示；播放器遇 429 显示「清理会话并重试」（清理后自动 reopen）；`player.js?v=20261107-playback-cleanup`、`settings.js` 的 import 带同版本号。
